# Getting Started with PageIndex

## What PageIndex does

PageIndex turns a long document into a tree: chapters, sections, and the page
range each one covers. When you ask a question, the model walks that tree the
way an analyst would — opening the sections that matter instead of guessing from
a similarity score — and then cites the exact page and block it used.

There is no vector database and no chunking step. The structure of the document
is the index.

## Reading an answer

Every answer carries citations. A citation names a document and a page; when the
document was indexed with block references it also names the block, so the
reader can highlight the sentence rather than the page.

Hover a citation to preview the page and the block. Choose **Open page** to read
it beside the conversation, and the document panel keeps one tab per document.

## Scoping a question

The composer's **Select Documents** control narrows a question to specific files.
Leave it empty and PageIndex searches the whole library — which is what you want
when you do not yet know which document holds the answer.

## Working across documents

Several documents can be open at once. Answers can compare them, and the sources
block groups references by document so you can see where each claim came from.

## What to try next

- Ask for a summary and check that every claim carries a citation.
- Ask a question that spans two documents.
- Open a citation, then use **Add page to chat** to pin that page into your next
  question.
